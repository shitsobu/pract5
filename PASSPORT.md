# Паспорт приложения и целевой среды

## 1. Общие сведения о приложении

**Название:** Attendance Service  
**Версия:** 0.5.0  
**Тип приложения:** HTTP-сервис  
**Язык программирования:** Python 3.12  
**Среда выполнения:** Docker  
**Инструмент развёртывания:** Docker Compose  

## 2. Назначение приложения

Attendance Service предназначено для предоставления информации о посещаемости. Приложение обрабатывает HTTP-запросы и возвращает сведения о количестве присутствующих, общем количестве участников и текущей версии сервиса.

Сервис может использоваться для демонстрации работы клиент-серверного взаимодействия, контейнеризации и организации хранения данных.

## 3. Пользователи приложения

Основными пользователями являются:

- разработчик, выполняющий настройку и сопровождение приложения;
- оператор, отвечающий за запуск и контроль состояния сервиса;
- клиентские программы, отправляющие HTTP-запросы.

## 4. Входные и выходные данные

**Входные данные:**
- HTTP-запросы к маршруту `/attendance`;
- HTTP-запросы к маршруту `/health`;
- параметры конфигурации через переменные окружения.

**Выходные данные:**
- JSON с информацией о посещаемости;
- JSON с состоянием приложения;
- HTTP-коды ответа;
- журналы выполнения приложения.

## 5. Программные зависимости

| Компонент | Назначение |
|---|---|
| Python 3.12 | Выполнение приложения |
| Docker | Контейнеризация |
| Docker Compose | Управление развёртыванием |
| Docker Volume | Постоянное хранение данных |
| Docker Healthcheck | Контроль работоспособности |

Приложение использует стандартную библиотеку Python и не требует установки дополнительных Python-пакетов.

## 6. Конфигурация приложения

| Переменная | Значение | Назначение |
|---|---|---|
| PORT | 8006 | Порт HTTP-сервера |
| MESSAGE | Attendance online | Сообщение сервиса |
| APP_VERSION | 0.5.0 | Версия приложения |
| DATA_DIR | /data | Каталог хранения данных |

## 7. Описание целевой среды

Развёртывание выполняется на локальном компьютере под управлением Windows с использованием Docker Desktop.

| Параметр | Значение |
|---|---|
| Операционная система | Windows |
| Платформа контейнеризации | Docker Desktop |
| Средство управления | Docker Compose |
| Тип сети | Изолированная внутренняя Docker-сеть |
| Имя сети | pract5-isolated |
| Имя контейнера | pract5-attendance |
| Имя Docker Volume | pract5-data |
| Порт приложения внутри контейнера | 8006 |

## 8. Сетевая конфигурация и ограничения

В соответствии с вариантом 6 используется изолированная сеть Docker с параметром `internal: true`.

Развёртывание и проверка приложения выполняются локально. Доступ к внешнему реестру контейнеров для запуска приложения не требуется.

Docker Compose настроен с параметром `pull_policy: never`, запрещающим автоматическую загрузку образа из внешнего реестра.

## 9. Управление данными

Состояние приложения хранится в файле `state.json` внутри каталога `/data`.

Для сохранения данных между перезапусками используется Docker Volume `pract5-data`.

Резервная копия хранится в каталоге `backup`.

## 10. Требования к работоспособности

Приложение считается работоспособным при выполнении следующих условий:

1. Docker-контейнер успешно запускается.
2. Состояние контейнера отображается как `healthy`.
3. Маршрут `/health` возвращает HTTP 200.
4. Маршрут `/attendance` возвращает корректный JSON.
5. Данные сохраняются после перезапуска контейнера.
6. Docker-образ может быть восстановлен из локального архива без обращения к внешнему реестру.

## 11. Ограничения и особенности

- Приложение развёртывается локально.
- Внешний доступ к сети контейнера ограничен.
- Используется заранее подготовленный Docker-образ.
- Восстановление образа выполняется из файла `attendance-v0.5.0.tar`.
- Данные приложения хранятся отдельно от контейнера.
