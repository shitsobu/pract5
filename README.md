# Attendance Service

## 1. Назначение приложения

Attendance Service — HTTP-приложение для получения информации о посещаемости. Приложение предоставляет данные о количестве присутствующих и общем количестве участников, а также информацию о версии и состоянии сервиса.

## 2. Версия

Текущая версия: **0.5.0**

## 3. Используемые технологии

- Python 3.12;
- Docker;
- Docker Compose;
- Docker Volume для постоянного хранения данных;
- HTTP API.

## 4. Структура проекта

- `pract3.py` — исходный код приложения;
- `Dockerfile` — инструкция сборки Docker-образа;
- `compose.yaml` — конфигурация развёртывания;
- `.dockerignore` — исключения при сборке образа;
- `env.example` — пример переменных окружения;
- `CHANGELOG.md` — история изменений;
- `release/` — офлайн-архив Docker-образа и контрольная сумма;
- `backup/` — резервная копия данных;
- `data/` — каталог данных приложения.

## 5. Развёртывание приложения

Для восстановления Docker-образа из локального архива выполните:

```cmd
docker load -i release\attendance-v0.5.0.tar
```

Запуск приложения без обращения к внешнему реестру:

```cmd
docker compose up -d --pull never
```

Проверка состояния контейнера:

```cmd
docker compose ps
```

## 6. Проверка работоспособности

Приложение предоставляет следующие HTTP-маршруты:

- `/health` — проверка состояния приложения;
- `/attendance` — получение информации о посещаемости.

Проверка состояния из контейнера:

```cmd
docker compose exec attendance python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8006/health').status)"
```

Ожидаемый результат: HTTP 200.

## 7. Хранение данных

Для сохранения состояния приложения используется Docker Volume `pract5-data`, подключённый к каталогу `/data` внутри контейнера.

Данные сохраняются при перезапуске и пересоздании контейнера.

## 8. Мониторинг

Для просмотра журналов приложения:

```cmd
docker compose logs --tail=20 attendance
```

Для просмотра использования ресурсов:

```cmd
docker stats --no-stream pract5-attendance
```

## 9. Остановка приложения

```cmd
docker compose down
```

Команда удаляет контейнер и сеть, но сохраняет Docker Volume с данными.

## 10. Восстановление после отказа

При потере локального Docker-образа необходимо:

1. Проверить целостность архива по SHA256.
2. Загрузить образ командой `docker load`.
3. Запустить приложение с параметром `--pull never`.
4. Проверить состояние контейнера и доступность маршрута `/health`.

Восстановление версии 0.5.0 из офлайн-архива было успешно проверено.
