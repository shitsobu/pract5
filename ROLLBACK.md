# План отката и восстановления Attendance Service

## 1. Общие сведения

**Приложение:** Attendance Service  
**Текущая версия:** 0.5.0  
**Docker-образ:** edu/attendance-service:v0.5.0  
**Среда:** Windows + Docker Desktop  
**Инструмент управления:** Docker Compose

## 2. Назначение плана

План предназначен для восстановления работоспособности приложения при ошибках развёртывания, повреждении или удалении Docker-образа, а также при проблемах с запуском контейнера.

Основная цель — обеспечить возврат приложения к рабочей версии без обращения к внешнему реестру контейнеров.

## 3. Возможные причины отката

- Удаление локального Docker-образа.
- Ошибка запуска контейнера.
- Некорректная работа приложения.
- Ошибка при обновлении версии.
- Потеря или повреждение локального Docker-образа.

## 4. Резервные копии

Для восстановления используются:

| Объект | Расположение |
|---|---|
| Docker-образ | `release/attendance-v0.5.0.tar` |
| Контрольная сумма | `release/SHA256.txt` |
| Резервная копия данных | `backup/state.json` |
| Конфигурация | `compose.yaml` |

## 5. Порядок отката

### 5.1. Остановка приложения

```cmd
docker compose down
```

Команда останавливает контейнер и удаляет его вместе с сетью. Постоянный том данных сохраняется.

### 5.2. Проверка целостности архива

```cmd
certutil -hashfile release\attendance-v0.5.0.tar SHA256
```

Ожидаемая контрольная сумма:

`43571636803bda705255adf4906e456c33e61147bb7cfb4597abc92ceb283d1c`

Если контрольная сумма не совпадает, архив использовать нельзя.

### 5.3. Восстановление Docker-образа

```cmd
docker load -i release\attendance-v0.5.0.tar
```

После загрузки необходимо проверить наличие образа:

```cmd
docker image ls edu/attendance-service
```

В списке должен присутствовать тег `v0.5.0`.

### 5.4. Повторный запуск

```cmd
docker compose up -d --pull never
```

Параметр `--pull never` запрещает обращение к внешнему реестру при запуске.

## 6. Восстановление данных

Если требуется восстановить файл состояния из резервной копии, необходимо остановить приложение и подготовить каталог данных.

Резервная копия находится в:

`backup/state.json`

Перед восстановлением необходимо убедиться, что файл существует и содержит корректные данные.

Восстановление выполняется в каталог данных приложения с сохранением структуры файла `state.json`.

## 7. Контроль после отката

После восстановления необходимо выполнить следующие проверки:

1. Выполнить `docker compose ps`.
2. Убедиться, что контейнер имеет статус `healthy`.
3. Проверить маршрут `/health`.
4. Проверить маршрут `/attendance`.
5. Убедиться в сохранности данных.
6. Проверить журналы приложения.

Успешным считается откат, при котором приложение запускается, возвращает корректные ответы и использует восстановленный Docker-образ.

В рамках практической работы был проведён тест восстановления:

- маршрут `/health` вернул HTTP 200.

**Вывод:** восстановление Docker-образа из офлайн-архива успешно проверено. План восстановления работоспособен.
